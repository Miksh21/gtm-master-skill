# Clay Template — Outbound Reply Enrichment

Concrete copy-paste pattern: when Instantly marks a lead as **"Lead replied"**, fire a Clay webhook → enrich the contact (incl. phone via BetterContact) → push to HubSpot + ping Slack channel. Reply latency collapses from hours/days to seconds.

## When to load

- "How do we enrich replies in real-time?"
- "Replies sit in Instantly inbox before SDR sees them — fix this"
- Building any "reply triggers downstream automation" pipeline

## Why this matters

Reply latency is a known killer of cold-outbound conversion. Most teams treat replies as a manual SDR babysitting task — interested leads sit in Instantly inbox, contact data is sparse, no phone number, CRM update lag.

This template makes the **reply itself the trigger** for parallel enrichment + CRM sync + sales alerting — no human in the critical path before the alert fires.

---

## The pipeline

```
Instantly "Lead replied" event
        ↓ (webhook)
Clay table receives: email + reply text + campaign metadata + LinkedIn URL (if available)
        ↓
BetterContact enriches phone number
        ↓
Clay maps fields → HubSpot (Email + Name + Job title + Company + Phone)
        ↓
Clay sends Slack alert: Contact name + title + reply text + phone number
```

## Setup steps

### Step 1 — Start from the Clay template
- Locate the published template URL (from workflows.io or build your own)
- "Create table using template" in Clay top-right
- Pick the workspace

### Step 2 — Connect Instantly → Clay
1. In the Clay table, locate the **webhook URL** generated by the template
2. Copy the webhook URL
3. In Instantly:
   - Open integration settings
   - Paste the Clay webhook URL
   - **Select event type: "Lead replied"** (this is the exact event name)
4. Save and activate

### Step 3 — Verify
- Trigger a test reply marked as "Replied" in Instantly
- Return to the Clay table — confirm a new row created
- Verify fields populated: Email + Reply text + Campaign metadata + LinkedIn profile URL (if available)

### Step 4 — Add BetterContact for phone
- In Clay, locate the **BetterContact API** column
- Paste your BetterContact API key in the column header
- Configure the column to run phone-number enrichment on each new row

### Step 5 — Connect HubSpot
- In Clay, connect your HubSpot workspace (OAuth)
- Map fields:
  - Email → Email
  - Name → First/Last
  - Job title → Title
  - Company → Company
  - Phone number → Phone

### Step 6 — Connect Slack
- Connect Slack workspace to Clay (OAuth)
- Select the channel for reply notifications
- Configure alert payload to include:
  - **Contact name + title**
  - **Reply text** (verbatim)
  - **Phone number**
  - Optional: company + Instantly campaign name

## What this template solves

Without it:
- Reply lands in Instantly inbox
- SDR sees it 2-24 hours later (Slack inbox not connected, sequencer notifications muted)
- Contact data is sparse — no phone number, partial company info
- CRM not updated until SDR manually does it
- Slack alert (if any) lacks context

With it:
- Reply triggers webhook → Clay row created within seconds
- BetterContact phone runs automatically
- HubSpot updated immediately with full contact + reply context
- Slack alert fires with phone + reply text → AE can call within minutes

## Routing extensions (optional)

Once the base template works, extend with:

### A. AI reply classification
Add a Clay AI column that reads the reply text and classifies:
- Positive intent (interested, asking questions)
- Objection (specific concern — pricing, timing, fit)
- Auto-reply / out-of-office (suppress alert)
- "Not interested" (mark in HubSpot, exit sequence)

### B. Tier-aware Slack routing
Different Slack channels by ICP tier:
- Tier 1 reply → #sales-tier1-replies + DM to assigned AE
- Tier 2/3 reply → #sales-general-replies
- Negative reply → no Slack alert, just CRM update

### C. Auto-create deals on positive intent
If classification = positive intent AND ICP score is Tier 1/2:
- Create HubSpot deal in correct pipeline + stage
- Associate Company + Contact
- Assign owner

- **Slack** — team alert destination

---

## Common failures

- **Wrong event name in Instantly** — must be "Lead replied" exactly. Other events (open, click) flood the pipeline with noise.
- **BetterContact API key in column header but not configured** — column appears empty. Verify the column is "Enabled" not just keyed.
- **HubSpot duplicate creation** — if email already exists, Clay creates a duplicate. Add lookup-first logic OR use upsert mode.
- **Slack alert too generic** — without reply text + phone, the alert is just noise. Payload specificity drives action.
