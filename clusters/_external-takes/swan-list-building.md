## Build list — swan-gtm/gtm-skills/skills/ido-goldberg/build-list · filed 2026-07-28
Source: https://github.com/swan-gtm/gtm-skills · cluster: list-building
Swan's list-building verb as a "column ladder": every list is a table where each column has an input, a cost tier, a run-when boolean, and a fallback. Strong overlap with list-building/tasks/build-prospect-list.md and the Clay column philosophy in enrichment; adds cost-ladder discipline the canon states less explicitly.
- ⚠️ contradicts [gtm-master minimum-size remedy, list-building/tasks/build-prospect-list.md:69,77 ("Tier 1 ≥ 50 contacts (if less, signal filters too narrow OR ICP too tight. Loosen one.")]: a thin audience here is a finding to surface, not a filter to loosen, "<50 companies: surface that to the user before proceeding. Thin niches usually need broader filters or a fundamentally different sourcing path (Apify directories, web research), not more retries of the same query", and the universal rule is to push back on briefs rather than pad ("quietly obeying a brief that contradicts the org's saved ICP segments" is an anti-pattern). Both sides. gtm-master: under 50 means loosen a criterion and ship; Swan/Ido: under 50 means stop and rethink the sourcing path or accept the thin niche.
- 🆕 new-angle: size the audience BEFORE sourcing: the first call is always a `size: 1` count probe; <50 surfaces to the user, >5,000 means "the brief is too loose. Ask for a tighter filter before pulling anything." Prevents "discovering after 20 tool calls that the niche is empty."
- 🆕 new-angle: the free-elimination pass as "the single biggest credit save in the flow", killing 60-80% of the pool at zero cost before any paid call: domain dedupe (normalize www/lowercase); hard re-filter of preview fields ("never treat a soft preview bucket as proof of a hard threshold", an 11-50 band is NOT a match for "20+ employees"); geo precision (state ≠ city); CRM cross-check dropping anything in an active sequence ("duplicate touches kill deliverability"); and a cheap LLM sniff test over names + domains killing obvious noise. Every paid column then gates on `icp_pass = true`.
- 🆕 new-angle: AI research columns as delegated one-question sub-agents: each column asks exactly ONE narrow question per row ("Does {domain} sell direct-to-consumer? yes/no/unclear"), never compound ("is DTC AND in SF AND sells electrical" = three columns); prompts name the pages to look at and force "unclear" over guessing; pilot on 10 rows first and "if 80%+ return 'unclear', the question is wrong — rewrite before scaling"; cheapest viable model, expensive reasoning only for genuine judgment calls.
- 🆕 new-angle: enum discipline for provider calls: always autocomplete enum-like filter values (industry, location, size band) before fetching and copy them verbatim, guessed enums cause "silent 0-result returns or 422 errors" (a real trace failed on `10000+` vs `10001+`); load tool schemas once at the top of a multi-tool plan; "same provider with different filters is NOT multi-source."
- 🆕 new-angle: coverage math and ordering: one source ≈ 60% of TAM, two ≈ 85%, three ≈ 92%; default source order = native preview → CRM closed-lost/churned/dormant → specialty source only for obvious gaps; companies FIRST then people ("never start with a broad people search like 'VP Sales at SaaS companies'"); tier A/B/C/D with D dropped BEFORE any contact work; contact caps per play (cold single-thread = 1 contact/company, ABM = 3-5 spanning the committee); email waterfall only on A/B tiers, validation after coalescing never during, role-based emails dropped, catch-all shipped only with explicit user acceptance of the deliverability hit; phone only on A-tier with a live cold-call motion.
- 🆕 new-angle: completion contract: the plan (columns + `icp_pass` definition) is shown BEFORE running; final summary shows size, tier breakdown, column completeness, and estimated credit cost for explicit approval; "the skill is not done until the list is saved or explicitly abandoned — don't end on 'want me to proceed?' with no list object created."
- ✅ supports [build-prospect-list.md multi-source + ICP-validation-before-enrichment, data-validation.md role-based removal, enrichment waterfall ordering]: dedupe by normalized domain then verified email; ≥50 rows moves processing into code instead of chat context.

## Map contacts — swan-gtm/gtm-skills/skills/ido-goldberg/map-contacts · filed 2026-07-28
Source: https://github.com/swan-gtm/gtm-skills · cluster: list-building
Buying-committee mapping for a NAMED account from relationship history first, prospect search last. Complements list-building/knowledge/abm/persona-mapping-framework.md with a relationship-signal layer canon lacks.
- 🆕 new-angle: known-relationship sources are mined BEFORE any prospect search, in order: CRM contacts/deals (role, last activity, still-here vs departed), each connected sender's SENT email folder filtered to the account's domain (everyone ever emailed, last touch, thread topic), meeting transcripts filtered by participant domain, and prior sequences (who was reached, who replied, who booked), aggregated to one row per human across all four sources.
- 🆕 new-angle: relationship-strength as a first-class taxonomy per person: cold / warm-via-X / former-contact-who-moved / former-contact-still-at-account / current-with-history / net-new-no-history, "these have very different next-move implications and the format makes that obvious at a glance"; net-new candidates are explicitly flagged "no relationship history" so they read differently from warm paths.
- 🆕 new-angle: movers are the headline: every past contact no longer at the account gets a current-employer check, because "a closed-lost champion now at a new target account is the highest-signal person to reach this quarter", if that person doesn't top the recommendations, "the skill missed the highest-value signal it exists to surface"; recently-joined current contacts flagged as new-to-role warm paths; intent is declared up front (net-new ABM / renewal prep / champion-tracking / de-single-threading) and shifts the weighting.
- 🆕 new-angle: gap honesty and credit thrift: personas with no candidate or weak coverage flagged at the TOP of the map, never buried; enrichment only for the slice the user is about to act on ("NEVER enrich every net-new contact"); the map is keyed strictly to the org's saved persona model ("never invent personas").
